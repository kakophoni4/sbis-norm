# API: отправка отчётов ФНС (НДС / Прибыль / 6-НДФЛ / РСВ)

Документ для интеграции **одного XML-отчёта** без книг (пакет «Отчетность 2-26» и аналоги).

Базовый URL: `http://<host>:8000/api/`  
Content-Type: `application/json`

**Важно:** эндпоинт `POST /api/sbis/send-nds-extra-1c/` (НДС с книгами 8/9) **не менялся** и остаётся для текущей привязки 1С.  
Этот документ описывает **новый** метод `send-report-1c`.

Сценарий СБИС (официальный API «Отчетность»):

1. Авторизация по сертификату  
2. `СБИС.ЗаписатьКомплект` (тип `ОтчетФНС`)  
3. `СБИС.ПодготовитьДействие` → «Отправить»  
4. `СБИС.ВыполнитьДействие`  

См. [API сервиса «Отчетность»](https://saby.ru/help/integration/api/reporting),  
[СБИС.ЗаписатьКомплект](https://saby.ru/help/integration/api/reporting/commands/rec_comp).

Прокси (NodeMaven) используются на всех HTTP-вызовах к СБИС, как в остальном сервисе.

Лимит СБИС: **не более 10** `ЗаписатьКомплект` в минуту.

## Типы отчётов

| report_type | Префикс ИдФайл | КНД | Имя формы (Сведения.Описание) |
|-------------|----------------|-----|--------------------------------|
| `nds` | `NO_NDS_` | 1151001 | Декларация по налогу на добавленную стоимость |
| `profit` | `NO_PRIB_` | 1151006 | Налоговая декларация по налогу на прибыль организаций |
| `ndfl6` | `NO_NDFL6…` | 1151100 | Расчет сумм НДФЛ… (форма 6-НДФЛ) |
| `rsv` | `NO_RASCHSV_` | 1151111 | Расчет по страховым взносам |
| `auto` | — | из XML | определяется по КНД / префиксу ИдФайл |

## 1. Отправка отчёта

`POST /api/sbis/send-report-1c/`

Авторизация HTTP сейчас не требуется. Подпись берётся **по ИНН** из CryptoPro (`Certificate` с private key).

### Тело запроса

```json
{
  "inn": "7725259701",
  "xml_b64": "<base64 XML>",
  "report_type": "auto",
  "dry_run": false
}
```

| Поле | Обязательно | Описание |
|------|-------------|----------|
| `inn` | да | ИНН организации (= ИННЮЛ в XML и ЭЦП) |
| `xml_b64` | да | XML отчёта в base64 (обычно windows-1251, без перекодирования). Алиасы: `main_xml_b64`, `main_b64` |
| `report_type` | нет | `auto` (по умолчанию) / `nds` / `profit` / `ndfl6` / `rsv` |
| `dry_run` | нет | `true` — только разбор, без вызова СБИС |

### Успех (HTTP 200), `dry_run: true`

```json
{
  "success": true,
  "comment": "DRY_RUN: данные приняты и распарсены, отправка в СБИС пропущена",
  "parsed": {
    "inn": "7725259701",
    "xml_inn": "7725259701",
    "kpp": "773001001",
    "kod_no": "7730",
    "report_type": "nds",
    "knd": "1151001",
    "form_name": "Декларация по налогу на добавленную стоимость",
    "idfile": "NO_NDS_…",
    "filename": "NO_NDS_….xml",
    "format_version": "5.12",
    "period": {"year": "2026", "code": "22"}
  }
}
```

### Успех (HTTP 200), боевая отправка

```json
{
  "success": true,
  "result": { "...": "ответ СБИС.ВыполнитьДействие" },
  "report_meta": {
    "report_type": "profit",
    "knd": "1151006",
    "form_name": "Налоговая декларация по налогу на прибыль организаций"
  },
  "send_meta": {
    "sbis_doc_id": "…",
    "sent_at": "2026-07-26T12:34:56+00:00",
    "sent_date": "2026-07-26"
  }
}
```

Сохраните `send_meta.sbis_doc_id` и `send_meta.sent_date` — для квитанции.

### Ошибки

| HTTP | Смысл |
|------|--------|
| 400 | Входные данные / несовпадение ИНН или типа |
| 401 | У ИНН нет валидной подписи (`csptest_name`) |
| 403 | Нет сертификата по ИНН |
| 404 | Ошибка СБИС при отправке |

## 3. Массовая отправка с сервера

Структура папки: `Орг/Тип/*.xml` (Тип: `НДС`, `Прибыль`, `6НДФЛ`, `РСВ`).

```bash
# положить пакет
# /opt/sbis-norm/media/otchetnost_2_26/...

cd /opt/sbis-norm

# проверка разбора
docker compose exec -T web python manage.py send_reports_from_folder \
  /app/media/otchetnost_2_26 --dry-run

# боевая отправка (пауза 7 с ≈ лимит 10/мин)
docker compose exec -T web python manage.py send_reports_from_folder \
  /app/media/otchetnost_2_26 --send --delay 7 \
  --report-json /app/media/otchetnost_2_26_result.json
```

Фильтры: `--inns 7725259701,9707029219` `--types nds,profit` `--limit 1`.

## Чеклист для 1С / интегратора

1. Собрать один XML отчёта (`NO_NDS_` / `NO_PRIB_` / `NO_NDFL6…` / `NO_RASCHSV_`).
2. Закодировать в base64 **как есть** (windows-1251).
3. Сначала `dry_run: true` — проверить `parsed.report_type`, `knd`, ИНН.
4. Затем `dry_run: false`.
5. Сохранить `send_meta`.
6. Периодически вызывать `get-receipt-pdf-1c` до получения `pdf_b64`.
7. Для НДС **с книгами покупок/продаж** по-прежнему использовать только `send-nds-extra-1c`.

---

## Замечания

1. ИНН в JSON, в XML (`ИННЮЛ`) и ЭЦП на сервере должны совпадать.
2. Отправка идёт через контейнер **web** (там установлены сертификаты CryptoPro).
3. Не путать с `send-nds-extra-1c` — разные контракты, разная привязка в 1С.

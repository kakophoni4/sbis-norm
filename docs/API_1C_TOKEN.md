# Авторизация 1С для отправки и статусов отчётов

Защищены три маршрута:

- `POST /api/sbis/send-nds-extra-1c/`;
- `POST /api/sbis/send-report-1c/`;
- `POST /api/sbis/report-statuses-1c/`.

Во всех запросах 1С обязана передавать HTTP-заголовок:

```http
X-1C-API-Token: <секретный-ключ>
Content-Type: application/json
```

Ключ хранится только на сервере в `/opt/sbis-norm/app.env`:

```env
ONEC_API_TOKEN=<случайная-длинная-строка>
```

Не передавать ключ в query-параметрах URL, теле JSON, имени файла или логах.
При отсутствующем либо неверном ключе сервис вернёт HTTP `401`:

```json
{"detail":"Необходим корректный заголовок X-1C-API-Token."}
```

## Ротация

Для смены ключа без остановки интеграции временно задать оба значения:

```env
ONEC_API_TOKEN=<новый-ключ>
ONEC_API_TOKEN_PREVIOUS=<старый-ключ>
```

Сначала перевести 1С на новый ключ, затем удалить
`ONEC_API_TOKEN_PREVIOUS` и перезапустить `web`.

## Контракты ручек

- Полный контракт НДС с книгами: `API_1C_NDS.md`.
- Полный контракт отправки одного XML-отчёта: `API_1C_REPORTS.md`.
- Полный контракт статусов, КВ и ИВ: `API_1C_REPORT_STATUSES.md`.

`send-nds-extra-1c` и старый `send-nds-extra` — разные HTTP-входы.
Первый принимает JSON/Base64 от 1С и защищён этим токеном. Второй принимает
multipart-файлы (`xml_file`, `book_files`) и пока не защищён этим ключом,
поскольку может использоваться отдельным старым клиентом. Оба в итоге
вызывают общий внутренний сервис отправки НДС `send_nds_extra`.

# API для 1С: отправка НДС и получение квитанции

Документ только для интеграции **отправки декларации НДС** и **получения PDF-справки/квитанции** из СБИС.

Базовый URL (прод): `http://<host>:8000/api/`  
Content-Type: `application/json`

Авторизация HTTP на эти эндпоинты сейчас не требуется.  
Подпись берётся **по ИНН** из CryptoPro на сервере (`Certificate` с private key).

**Критично:** `inn` в JSON, `ИННЮЛ` в XML и ЭЦП в CryptoPro должны совпадать.  
Иначе `dry_run` может пройти, а реальная отправка в СБИС/ФНС — нет или уйдёт «не тем» подписантом.

---

## Сценарий для 1С

```
1С                              Django API                         СБИС / ФНС
───                             ──────────                         ─────────
собрать NO_NDS XML
(+ книги 8/9) → base64
        │
        ▼
POST /api/sbis/send-nds-extra-1c/
  inn, main_xml_b64,
  book_xml_b64_list
  dry_run=false  ──────────►  подпись ЭЦП по ИНН
                              auth СБИС
                              ЗаписатьКомплект / Отправить
                     ◄──────  success + send_meta
                              { sbis_doc_id, sent_date, sent_at }

сохранить send_meta
        │
        │  (через N минут —
        │   квитанция появляется не сразу)
        ▼
POST /api/sbis/get-receipt-pdf-1c/
  inn, sbis_doc_id, sent_date
                     ──────────►  архив документа в СБИС
                     ◄──────  pdf_b64   или 400 «ещё нет»
```

## 1. Отправка декларации НДС

`POST /api/sbis/send-nds-extra-1c/`

### Тело запроса

```json
{
  "inn": "9707039440",
  "main_xml_b64": "<base64 XML основного файла NO_NDS_...>",
  "book_xml_b64_list": [
    "<base64 XML книги покупок NO_NDS.8_...>",
    "<base64 XML книги продаж NO_NDS.9_...>"
  ],
  "dry_run": false
}
```

| Поле | Обязательно | Описание |
|------|-------------|----------|
| `inn` | да | ИНН организации (= ИНН в XML и ЭЦП) |
| `main_xml_b64` | да | Основной XML декларации в base64. Алиасы: `xml_b64`, `main_b64` |
| `book_xml_b64_list` | нет* | Список base64 книг. Алиасы: `books_b64`, `book_b64_list`. Элемент — строка или `{ "b64": "..." }` |
| `dry_run` | нет | `true` — только разбор/проверка имён книг, **без** отправки в СБИС |

\*Для полноценной декларации книги обычно нужны. Имена файлов книг в основном XML (`КнигаПокуп` / `КнигаПрод`) должны совпасть с `ИдФайл` переданных book-XML.

### Успех (HTTP 200), боевая отправка

```json
{
  "success": true,
  "result": { "...": "ответ СБИС.ВыполнитьДействие" },
  "send_meta": {
    "sbis_doc_id": "73696d74-690b-4acd-82ff-176a37c16d7c",
    "sent_at": "2026-07-10T12:34:56+00:00",
    "sent_date": "2026-07-10"
  }
}
```

1С **обязана сохранить** `send_meta.sbis_doc_id` и `send_meta.sent_date` — они нужны для получения квитанции.

### Успех (HTTP 200), `dry_run: true`

```json
{
  "success": true,
  "comment": "DRY_RUN: данные приняты и распарсены, отправка в СБИС пропущена",
  "parsed": {
    "inn": "9707039440",
    "main": {
      "idfile": "NO_NDS_...",
      "filename": "NO_NDS_....xml"
    },
    "books": ["NO_NDS.8_....xml", "NO_NDS.9_....xml"],
    "expected_in_main": {
      "buy": "NO_NDS.8_....xml",
      "sell": "NO_NDS.9_....xml"
    }
  }
}
```

### Ошибки

| HTTP | Смысл |
|------|--------|
| 400 | Входные данные / имена книг не совпали с основным XML |
| 401 | У ИНН нет валидной подписи (`csptest_name`) |
| 403 | Нет сертификата по ИНН |
| 404 | Ошибка СБИС при отправке (детали в `error`) |

Типичный вид ошибки:

```json
{
  "success": false,
  "comment": "Ошибка входных данных",
  "error": { "message": "..." }
}
```

### Пример curl (dry_run)

```bash
curl -sS -X POST "http://<host>:8000/api/sbis/send-nds-extra-1c/" \
  -H "Content-Type: application/json" \
  -d '{
    "inn": "9707039440",
    "main_xml_b64": "'"$MAIN_B64"'",
    "book_xml_b64_list": ["'"$BOOK8_B64"'","'"$BOOK9_B64"'"],
    "dry_run": true
  }'
```

## 2. PDF квитанции (справка) из архива СБИС

`POST /api/sbis/get-receipt-pdf-1c/`

### Тело запроса

```json
{
  "inn": "9707039440",
  "sbis_doc_id": "<из send_meta после отправки>",
  "sent_date": "YYYY-MM-DD"
}
```

| Поле | Обязательно | Описание |
|------|-------------|----------|
| `inn` | да | тот же ИНН, что при отправке |
| `sbis_doc_id` | да | из `send_meta.sbis_doc_id` |
| `sent_date` | да | из `send_meta.sent_date` (`YYYY-MM-DD`) |

### Успех (HTTP 200)

```json
{
  "success": true,
  "pdf_b64": "<base64 PDF>"
}
```

### Ошибка (HTTP 400)

Квитанция ещё не появилась в архиве, либо неверные параметры:

```json
{
  "success": false,
  "comment": "...",
  "error": { "message": "..." }
}
```

**Важно:** справка ФНС появляется не мгновенно. Сразу после отправки в архиве часто есть только PDF самой декларации/книг (`PDF/NO_NDS*`), а не квитанция.  
1С должна **повторять** запрос через несколько минут (например, каждые 5–15 мин) с теми же `inn` / `sbis_doc_id` / `sent_date`, пока не получит `pdf_b64`.

---

## Что должна сделать 1С (чеклист)

1. Собрать XML декларации `NO_NDS_...` и книг `NO_NDS.8_...` / `NO_NDS.9_...`.
2. Закодировать файлы в base64 **как есть** (обычно windows-1251).
3. Сначала вызвать отправку с `"dry_run": true` — проверить `parsed` и совпадение имён книг.
4. Затем вызвать с `"dry_run": false`.
5. Сохранить `send_meta.sbis_doc_id` и `send_meta.sent_date`.
6. Периодически вызывать `get-receipt-pdf-1c` до получения `pdf_b64`.
7. Сохранить PDF как вложение к отчёту.

---

## Замечания интегратору

1. ИНН в JSON, в XML (`ИННЮЛ`) и ЭЦП на сервере должны совпадать.
2. Имена книг в основном XML (`КнигаПокуп` / `КнигаПрод`) = `ИдФайл` переданных book-XML.
3. XML обычно в windows-1251; в base64 передаётся без перекодирования.
4. Реальная отправка (`dry_run: false`) уходит в СБИС/ФНС — для отладки контракта сначала `dry_run: true`.
5. Ошибка СБИС «Регистрация клиента еще не завершилась» — статус кабинета в СБИС, не формат запроса 1С.
6. Для dry_run можно подставить тестовый XML; для боевой отправки — только совпадающий ИНН и рабочие XML.
